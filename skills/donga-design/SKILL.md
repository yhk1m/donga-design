# 동아 디자인 (donga-design)

**당토 디자인(dangto-design)의 규격을 그대로 따르고, 색만 동아출판 CI로 고정한 스킬이다.** 정보의 위계와 덜어냄으로 완성도를 만드는 당토의 원칙, 문구, 금지 목록, 점검표는 하나도 바꾸지 않았다. 여기에 세 가지를 더했다.

1. **CI 색 고정:** 주색 동아 빨강, 보조색 동아 먹. 테마색을 고르는 단계가 없다.
2. **CI 로고와 열림 애니메이션:** 붙어 있던 ㄷ과 ㅇ이 양끝으로 벌어지며 "동아출판"이 열린다.
3. **동아출판 제작 가이드의 내용 규칙:** 단일 `index.html`, `.dc-content` 래퍼, 보안 금지 목록, 접근성 기준, 제출 점검. (가이드의 디자인은 따르지 않는다. 겉모양은 늘 이 스킬을 따른다.)

**쓰는 곳:** 학습 활동, 시뮬레이션, 퀴즈, 교사용 도구, 관리 화면, 설정, 입력 양식, 목록, 상태 화면
**쓰지 않는 곳:** 홍보용 랜딩 페이지, 슬라이드

## 0. 시작 절차

코드를 쓰기 전에 아래를 정한다. 사용자가 이미 말했거나 프로젝트에 정해져 있으면 묻지 않는다.

1. **색은 정하지 않는다.** `assets/tokens.css`에 CI 색이 고정되어 있다. 코드에 색 값을 직접 쓰지 말고 역할 변수(`--accent`, `--text-muted` 등)만 쓴다. 사용자가 다른 색을 요구하면 동아 디자인 범위를 벗어난다고 알리고 따른다.
2. **실행 방식:** 기본은 두클래스 방식(단일 `index.html` + `assets/`). 사용자가 React, 서버, 독립 웹앱을 분명히 말할 때만 `references/douclass.md` 4번을 그에 맞게 푼다. 보안과 접근성 규칙은 어느 경우에도 지킨다.
3. **밀도 다이얼:** 묻지 않고 화면 종류로 정한다. 학생이 쓰는 화면은 `편안`, 교사, 운영자가 쓰는 관리 화면과 표는 `촘촘`.
4. **개성 다이얼:** `담백`이 기본. 사용자가 브랜드, 개성, 홍보를 말할 때만 `브랜드`(모서리 0).
5. **로고를 넣을지:** 독립 도구의 시작 화면, 표지에는 열림 로고를 넣는다. 두클래스에 올리는 자료에는 넣지 않는다(뷰어가 이미 보여 준다). `references/brand.md` 4번.
6. **부품:** 처음부터 그리지 말고 `references/components.md`를 읽고 TDS, SEED 문서의 구조와 동작을 따라 새로 짠다. 두클래스 자료에는 패키지를 설치하지 않는다.

그다음 시작 틀을 만든다.

```html
<!doctype html>
<html lang="ko">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>화면 이름</title>
<style>
  /* assets/tokens.css 내용을 그대로 붙인다 */
  /* 로고를 쓰면 assets/logo/logo-open.snippet.html 의 <style> 내용을 붙인다 */
  /* 이 화면 규칙: 모두 .dc-content .클래스 형태 */
</style>
</head>
<body style="margin:0">
<div class="dc-content" id="app">
  <!-- 화면 -->
</div>
<script>
(function () {
  var root = document.getElementById('app');
  // DOM은 root 안에서만 찾고, createElement + textContent + addEventListener로만 만든다
})();
</script>
</body>
</html>
```

글꼴 파일은 `assets/fonts/`의 woff2 4개와 `OFL-Pretendard.txt`를 제출 폴더 `assets/fonts/`로 복사한다. 외부 CDN을 쓰지 않는다.

## 1. 원칙 6개 (당토와 같음)

1. **배우지 않아도 바로 이해된다.** 설명이 필요하면 설계가 잘못된 것이다. 3초 안에 화면 목적이 보여야 한다.
2. **한 화면에 목표 하나, 주요 버튼 하나.** 채운 빨강 버튼은 화면마다 하나만 둔다.
3. **덜어낸다.** 여백으로 나눌 수 있으면 선을 긋지 않는다. 기능, 장식, 문구를 더하는 건 마지막 수단이다.
4. **결과를 예측할 수 있게 한다.** 누르기 전에 결과, 비용, 조건을 보여 준다. 되돌릴 수 없는 행동은 확인을 받거나 되돌리기를 준다.
5. **사용자 머릿속 개념대로 묶는다.** 회사 조직, 데이터베이스 표, 상품 구분대로 나누지 않는다.
6. **빈 화면, 오류, 로딩도 기본 화면처럼 설계한다.** 행복한 경로만 그리고 끝내지 않는다.

## 2. 핵심 시각 규칙

값은 `references/tokens.md`, CI 색은 `references/brand.md`에 있다. 여기서는 어기기 쉬운 것만 적는다.

**색**
- 주색 동아 빨강(라이트 `#d4153a`, 다크 `#ff5a72`)은 주요 행동, 선택 상태, 진행 막대에만. 링크마다, 아이콘마다, 큰 면에 칠하지 않는다. 빨강이 넓어지면 화면 전체가 경고처럼 보인다.
- CI 빨강 `#ec1940` 원색은 로고와 브랜드 그래픽에만. 흰 글자 대비가 모자라서 버튼에는 쓰지 않는다.
- 보조색 동아 먹(`#333333`, 다크 `#e8e8e8`)은 머리 띠, 로고, 차트 둘째 계열에만. 버튼과 링크에는 쓰지 않는다. 셋째 색은 없다.
- **빨강 주색과 오류를 구분한다.** 위험색은 주황 쪽 빨강(`#b42318`)이고, 오류와 위험은 늘 아이콘과 문구를 함께 쓴다. 오답 표시에 주색을 쓰지 않는다.
- 회색은 남색 기운이 살짝 도는 10단계. 순수 검정(#000) 글자는 없다.
- 바탕은 연한 회색, 그 위에 흰 면. 흰 면끼리는 그림자 대신 바탕색 차이로 나눈다.
- 글자 위계는 회색 3~4단계로 만든다. 크기를 키우기 전에 회색 단계부터 쓴다.
- 자료 색(지도 화살표, 지역, 반, 기후 종류, 차트 계열)은 `--data-1`~`--data-4`(파랑, 주황 갈색, 청록, 회색, 라이트와 다크 값 따로)를 쓴다. 상태색(`--info`, `--warning` 등)을 자료 색으로 빌려 쓰지 않는다. 계열이 더 필요하면 같은 밝기의 색을 더하되 빨강 쪽은 피한다. 핵심 계열 하나만 강조할 때는 주색을 써도 된다.

**다크 모드**
- 시스템 설정을 따르고, 래퍼나 영역에 `data-theme="light|dark"`로 바꿀 수 있다. 바꾸는 버튼을 둘 때는 "자동, 밝게, 어둡게" 세 가지로, 고른 값은 저장하지 않는다.
- 라이트를 뒤집지 않는다. 바탕은 `#121418`, 위로 올라온 면일수록 밝게. 그림자 대신 면의 밝기 차이로 높이를 나타낸다.
- 다크의 빨강 버튼 위 글자는 흰색이 아니라 아주 어두운 빨강(`#2a0610`)이다. 토큰이 알아서 바꾼다.
- 로고는 다크에서 ㄷ과 글자가 밝은 회색이 되고 빨강은 그대로다(`--logo-ink`).

**글자**
- Pretendard(동봉 파일). 굵기 400, 500, 600, 700, 촘촘 모드는 400, 600만.
- 본문: 편안 16px, 촘촘 13~14px. 학생 화면은 16px 아래로 내리지 않고, 오래 읽는 글은 18px. 어떤 경우에도 12px 아래는 없다. 입력 칸은 16px 이상.
- 큰 제목은 자간 음수(-0.025em), 작은 글씨는 0. 바뀌는 숫자는 `tabular-nums`. 크기는 rem.
- viewBox로 줄어드는 SVG 안 글자는 가장 좁은 화면(390px)에서 실제 크기가 12px 이상(학생 화면 라벨은 14px 이상)이 되도록 viewBox 기준 크기를 잡는다. 실제 크기 = 글자 크기 × (그림 표시 폭 ÷ viewBox 폭).

**브라우저 기본 부품**
- 스크롤바, 선택 상자와 펼친 목록, 체크와 라디오, 슬라이더, 입력 칸, 자동 완성 바탕까지 테마를 따르게 한다. 본문만 다크로 바뀌고 펼친 목록과 스크롤바가 하얗게 남으면 안 된다.
- 태그 선택자를 쓸 수 없으므로 `dc-select`, `dc-input`, `dc-scroll`, `dc-dialog`, `dc-file` 클래스를 붙인다. `<head>`에 `<meta name="color-scheme" content="light dark">`를 넣는다. 자세한 것은 `references/patterns.md`의 "드롭다운, 메뉴, 스크롤바".

**간격, 모서리, 그림자, 움직임**
- 간격은 4px 단위. 화면 좌우 여백 16~20px.
- 모서리: 배지 4, 버튼 10, 카드 16, 시트 20. 브랜드 개성은 모두 0(CI의 각진 ㄷ).
- 그림자는 떠 있는 것에만, 투명도 0.12 이하.
- 반응 150ms, 전환 250ms, 큰 전환 400ms 이하. `prefers-reduced-motion`을 따른다. 장식 애니메이션은 넣지 않는다. **예외는 로고 열림 하나**뿐이다(화면마다 한 번, 1.5초, `references/brand.md` 5번).
- 누르는 영역은 최소 44px, 교실 화면은 48px.

## 3. 태블릿 (특히 신경 쓴다)

동아출판 자료는 교실에서 학생 태블릿으로 가장 많이 연다. 휴대폰 화면을 늘린 것으로 끝내지 말고 `references/tablet.md`를 읽고 태블릿 배치를 따로 만든다. 핵심만 적는다.

- **세 구간을 설계한다:** 휴대폰(744px 미만), 태블릿 세로(744~1023px), 태블릿 가로(1024px 이상, 가로 방향). 점검도 390, 820, 1180 폭으로 한다.
- **세로 태블릿:** 한 칸, 본문 폭은 44rem에서 멈추고 가운데. 짧은 선택지는 2열.
- **가로 태블릿:** 두 칸. 왼쪽 60%에 그림이나 시뮬레이션(`sticky`로 고정), 오른쪽 40%에 조작, 설명, 문제, 주요 버튼. 첫 화면 핵심이 높이 820px(두클래스 A 방식이면 약 700px) 안에 스크롤 없이 들어와야 한다. 주요 버튼을 화면 전체 폭으로 늘이지 않는다.
- **손:** 터치 48px(`pointer: coarse`이면 토큰이 알아서 올린다), 자주 누르는 조작은 오른쪽 칸 아래, hover로만 보이는 정보 없음.
- **방향 바꾸기:** 세로와 가로를 바꿔도 고른 값과 진행 상태가 그대로. SVG, canvas는 `ResizeObserver`로 실제 폭에 맞춰 다시 그려서, 넓은 화면에서 그림 속 글자가 같이 커지지 않게 한다.
- 대화상자는 태블릿에서 가운데 대화상자(최대 32rem). 바텀시트는 휴대폰에서만.

| | 담백 (기본) | 브랜드 |
|---|---|---|
| 모서리 | 기본 단계 | 모두 0 |

다이얼은 겉모양만 바꾼다. 원칙, 문구, 금지 목록, 보안 규칙은 어느 조합에서도 같다.

## 5. 구조와 보안 (동아출판 제작 가이드)

자세한 내용은 `references/douclass.md`. 코드를 쓰기 전에 한 번 읽는다. 어기기 쉬운 것만 적는다.

- **한 파일:** CSS, JS, 문항 데이터는 모두 `index.html` 안에. 이미지, 소리, 글꼴만 `./assets/` 상대 경로. 외부 CDN, 외부 글꼴, `fetch`, `<script src>`, `<link>`, `iframe` 없음.
- **래퍼:** 모든 선택자는 `.dc-content`로 시작한다. 태그 선택자, `:root`, `*`, `!important` 없음.
- **위치:** `position: fixed` 대신 래퍼 안 `absolute`나 `sticky`. `z-index` 100 이하.
- **DOM:** `innerHTML` 등 HTML 문자열 넣기 없음. `createElement`, `textContent`, `addEventListener`. `onclick` 같은 속성 없음.
- **바깥 접근 없음:** `eval`, `cookie`, `window.open`, `location` 이동, `parent`, `postMessage`, `Worker`.
- **저장:** 기본은 저장하지 않는다. 학생 개인정보는 모으지 않는다. 그림, PDF 바로 저장 버튼 대신 인쇄 창의 PDF 저장.
- **접근성:** 키보드로 모든 조작, 보이는 초점, `aria-pressed`와 `aria-checked`, Esc로 팝업 닫고 초점 되돌리기, 끌기에는 누르기 대안, 그래프에는 표 대안, 200% 확대, 확대 막지 않기.
- 플랫폼에 있는 제목, 공유, 수업 도구 버튼을 다시 만들지 않는다. 공식 로고와 저작권 문구는 받은 것만 쓴다.

## 6. 모범 예시

`assets/examples/climate-quiz/index.html`(그림: 휴대폰 `climate-quiz.png`, 태블릿 `climate-quiz-tablet.png`)은 이 스킬을 그대로 적용한 학생용 퀴즈다. 열림 로고 시작 화면, 한 화면에 질문 하나, 고른 것만 빨강, 그래프 + 표 대안, 정답과 오답을 성공색, 위험색 + 아이콘 + 문구로, 하단 sticky 버튼, 태블릿 세로 2열 선택지와 가로 두 칸(그래프 고정), 폭에 맞춰 다시 그리는 그래프, 자동/밝게/어둡게, 키보드 방향키 고르기, `.dc-content` 래퍼와 금지 API 없는 코드까지 담았다. 화면 종류가 같으면 먼저 열어 보고 구조와 크기를 참고하되 그대로 베끼지 않는다.

관리 화면은 당토 예시와 같은 원칙(`references/patterns.md`의 분할 관리 화면)을 따른다.

## 7. 화면 패턴

`references/patterns.md`에 목록 줄, 카드 묶음, 버튼 위계, 하단 고정 버튼, 대화상자, 토스트, 빈 화면, 오류, 로딩, 입력 양식, 분할 관리 화면 규칙이 있다. 화면을 만들기 전에 해당 패턴을 읽는다. (고정 위치는 `sticky`, `absolute`로 바꿔 읽는다.)

- **목록 한 줄:** 왼쪽 아이콘(선택) + 가운데 제목과 회색 보조 글 + 오른쪽 값이나 화살표. 줄 전체가 눌린다.
- **버튼 위계:** 채움(빨강) → 연한 빨강 바탕 → 회색 바탕 → 글자만. 모바일 주요 행동은 하단 sticky 버튼.
- **관리 화면:** 숫자 카드를 늘어놓지 말고, 할 일 목록과 선택한 항목의 상세를 나란히. 칸은 두 개까지.

## 8. 문구

`references/writing.md`에 바꿔 쓰기 예시가 있다. 화면 문구를 쓰기 전에 읽는다.

- 해요체. "되어요"는 "돼요". 과한 존칭은 쓰지 않는다.
- 능동문, 긍정문. 할 수 없는 것보다 할 수 있는 것을 말한다.
- 일상어로. 고등학생이 바로 읽을 수 있게.
- 버튼은 누른 결과("확인" 대신 "정답 확인하기"). 1~3단어, 마침표 없음. 닫는 버튼은 "닫기".
- 오류 문구는 무엇이 일어났는지와 어떻게 하면 되는지를 함께. 기술 용어 금지.
- 숫자는 아라비아 숫자. 느낌표는 아낀다.
- 보이는 글에 가운데 점(·)과 긴 대시(—)를 쓰지 않는다.
- 옵션 라벨에 "추천"을 쓸 때 "추시"로 잘못 쓰지 않았는지 확인한다.
- "교육용이니 자유 이용" 같은 권리 문구를 임의로 넣지 않는다.

## 9. 금지 목록

**전체 (당토와 같음)**
- UI에 이모지. 아이콘은 선 SVG(굵기 1.5~2px, 끝 둥글게).
- 순수 검정 글자, 순수 검정 다크 바탕
- 한 화면에 채운 빨강 버튼 여러 개
- 여백으로 충분한데 넣은 구분선과 테두리 상자
- 진한 그림자, 강한 그라디언트, 빛나는 효과, 유리 효과, 파티클 같은 장식
- 들어오자마자 뜨는 팝업, 겹쳐 뜨는 팝업, 거절할 수 없는 선택
- 미리 깔아 두는 경고 문구, 오류가 아닌데 쓰는 느낌표 아이콘
- 즉시 끝나는 작업의 로더, 스켈레톤과 스피너를 같이 쓰기
- 누를 수 없는데 버튼처럼 보이는 것
- 선택 표시용 왼쪽 강조 줄을 둥글게 그리기 (모서리 없는 일자 막대로)

**동아 디자인에서 더한 것**
- CI 빨강으로 큰 면 칠하기, 빨강 바탕 머리 띠, 빨강 그라디언트
- 로고 늘이기, 색 바꾸기, 그림자, 로고 열림 애니메이션 되풀이나 시간 바꾸기
- 색만으로 오답, 오류 알리기
- 동아출판 제작 가이드의 디자인(색, 글꼴, 꾸밈)을 가져오기

**관리 화면에서 피할 AI 티 (당토와 같음)**
- 같은 크기 숫자 카드 4개를 맨 위에 늘어놓기
- 모든 줄 끝에 강조색 "보기" 링크. 줄 전체를 누르게 하고, 행동 버튼은 선택한 항목에만
- 모든 줄에 색 태그. 처리할 것만 색, 나머지는 회색, 끝난 것은 접기
- 의미 없는 로고 네모, 이름 첫 글자 동그라미 아바타
- 제목 위 작은 영문 대문자 설명 글(eyebrow)
- 몇십 줄밖에 안 되는데 쪽 나누기
- 할 일이 남았는데 마무리 버튼을 강조하기
- 한 화면을 세 칸 이상으로 나누기
- 왼쪽 메뉴, 숫자 카드, 검색창, 표 순서의 틀을 습관처럼 쓰기

## 10. 완성 전 점검

**자동 점검 두 개를 돌린다.** Node가 있으면 HTML을 만든 뒤 아래를 실행하고, 끝 코드가 0이 될 때까지 고친다. "오류"는 모두 고치고, "직접 확인할 것"은 하나씩 보고 판단한다.

```
node "<이 스킬 폴더>/scripts/rules-check.mjs" <제출폴더 또는 index.html>   # 구조, 보안, 접근성 (Chrome 필요 없음)
node "<이 스킬 폴더>/scripts/check.mjs" <index.html>                        # 화면 디자인 (Chrome 필요)
```

`check.mjs`는 라이트와 다크, 휴대폰(390), 태블릿 세로(820), 태블릿 가로(1180) 폭에서 글자 대비, 12px 미만 글자, 순수 검정, 이모지, 가운데 점과 긴 대시, 터치 영역, 채운 강조색 버튼 수, 가로 넘침을 찾는다. 첫 화면만 보므로, 숨은 화면(문제 풀이, 결과)은 직접 열어 확인한다. `rules-check.mjs`는 글자 맞추기 점검이라 두클래스 검사기를 대신하지 못한다.

- [ ] 3초 안에 화면 목적이 보이는가
- [ ] 채운 빨강 버튼이 화면마다 하나뿐인가, 빨강을 쓴 곳이 주요 행동과 선택 상태뿐인가
- [ ] 오류, 오답, 위험 표시에 아이콘과 문구가 함께 있는가
- [ ] 여백으로 충분한 곳에 선이나 상자를 넣지 않았는가
- [ ] 빈 화면, 오류, 로딩 상태를 만들었는가 (한 장짜리 시안이면 각 상태에서 무엇을 보여 줄지 보고에 적는다. 불러오는 자료가 없는 학습 활동이면 오류와 로딩은 "해당 없음"이라고 보고하고, 대신 빈 입력, 아직 고르지 않음, 다 풀었음 상태를 챙긴다)
- [ ] 결과 화면처럼 할 일이 끝난 화면은 다음 행동이 분명하면 그것 하나를 채움 버튼으로, 고를 거리가 대등하면(다시 풀기, 처음으로) 회색 버튼으로 둔다
- [ ] 버튼 라벨이 누른 결과를 말하는가, 해요체인가, 가운데 점과 긴 대시가 없는가
- [ ] 다크 모드가 되고, 대비 4.5:1, 터치 영역 44px을 지켰는가
- [ ] 다크 모드에서 스크롤바, 펼친 선택 상자 목록, 체크와 라디오, 입력 칸, 직접 만든 메뉴까지 어둡게 바뀌는가 (`dc-select`, `dc-input`, `dc-scroll` 클래스와 color-scheme 메타 태그)
- [ ] 휴대폰 폭(390px)에서 가로로 넘치지 않는가 (헤드리스 Chrome은 창 최소 폭이 약 500px이다. 390px 너비 iframe에 넣어 찍는다)
- [ ] 태블릿 세로(820)와 가로(1180 × 820)를 따로 설계했는가. 가로에서 두 칸, 첫 화면 핵심이 스크롤 없이 보이는가, 방향을 바꿔도 상태가 남는가
- [ ] 키보드만으로 모든 조작이 되고, 초점이 보이는가
- [ ] 로고를 넣었다면 CI 그대로이고, 열림은 화면마다 한 번인가
- [ ] `index.html` 하나와 `assets/`뿐이고, 인터넷을 끄고 새 폴더에서 열어도 되는가
- [ ] 두클래스에 올릴 자료면 `references/douclass.md` 9번 제출 점검과 담당자 검사기까지 거쳤는가
