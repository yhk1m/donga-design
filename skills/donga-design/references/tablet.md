# 태블릿 레이아웃

동아출판 자료는 교실에서 학생 태블릿(아이패드, 갤럭시 탭)으로 여는 일이 가장 많다. 휴대폰 화면을 늘리거나 데스크톱 화면을 줄인 것으로 끝내지 않고, 태블릿을 따로 설계한다.

## 1. 기준 폭

| 기기 | 세로 | 가로 |
|---|---|---|
| 아이패드 10세대, Air | 820 × 1180 | 1180 × 820 |
| 아이패드 미니 | 744 × 1133 | 1133 × 744 |
| 아이패드 Pro 12.9 | 1024 × 1366 | 1366 × 1024 |
| 갤럭시 탭 S 시리즈 | 800 × 1280 안팎 | 1280 × 800 안팎 |

- 구간: 휴대폰 `< 744px`, 태블릿 세로 `744~1023px`, 태블릿 가로와 작은 노트북 `1024~1366px`.
- 폭만 보지 말고 방향(`orientation`)과 높이도 본다. 가로 태블릿은 높이가 744~820px뿐이다. 두클래스 뷰어 A 방식이면 머리와 꼬리 때문에 더 줄어든다. **가로 태블릿에서 첫 화면 핵심(그림과 조작)이 스크롤 없이 한 화면에 들어오게** 한다.
- 터치 기기인지는 폭이 아니라 `@media (pointer: coarse)`로 판단한다. 태블릿에 키보드를 붙이고 마우스를 쓸 수도 있다.

## 2. 배치

**세로 태블릿 (744~1023px)**
- 한 칸으로 쌓되 휴대폰보다 넓게 쓴다. 본문 폭은 40~44rem(640~700px)에서 멈추고 가운데 둔다. 글줄이 너무 길면 읽기 어렵다.
- 그림(시뮬레이션, 지도, 그래프)은 폭을 다 쓰고, 그 아래 조작과 설명.
- 선택지가 4개 이하이고 짧으면 2열 격자로 놓아 스크롤을 줄인다.

**가로 태블릿 (1024px 이상, 가로 방향)**
- **두 칸이 기본이다.** 왼쪽 넓은 칸(약 60%)에 그림이나 시뮬레이션, 오른쪽 칸(약 40%, 최소 320px)에 조작, 설명, 문제. 칸은 두 개까지(당토 규칙).
- 오른쪽 칸만 스크롤되고 왼쪽 그림은 `position: sticky`로 제자리에 둔다. 학생이 문제를 풀면서 그림을 계속 볼 수 있다.
- 주요 버튼은 오른쪽 칸 아래에 둔다. 화면 전체 폭의 하단 버튼으로 늘이지 않는다(1180px 폭의 버튼은 누르기도 읽기도 어렵다). 버튼 폭은 칸 폭을 따르고 최대 28rem 정도.
- 가로 태블릿에서 그림 높이는 `min(화면 높이 - 머리 높이 - 여백, 그림 비율에 맞는 높이)`로 잡아 잘리지 않게 한다. `100dvh`를 쓴다(`100vh`는 아이패드 사파리 주소창 때문에 넘친다).

**모든 태블릿**
- 화면 좌우 여백: 세로 24px, 가로 32px.
- 휴대폰 화면을 그대로 늘린 한 줄 목록, 화면 폭 꽉 찬 입력 칸을 피한다. 폭을 제한하거나 칸을 나눈다.
- 대화상자는 바텀시트 대신 가운데 대화상자(최대 폭 28~32rem). 바텀시트는 휴대폰에서만.

## 3. 손과 터치

- 누르는 영역 48px 이상(`--touch-class`). 교실에서 학생이 책상 위에 태블릿을 두고 손가락으로 누른다.
- 가로로 들고 쓸 때 엄지가 닿는 곳은 화면 양 옆 아래다. 자주 누르는 조작(다음, 확인, 계절 고르기)은 오른쪽 칸 아래쪽에 모은다. 화면 맨 위 가운데에는 자주 누르는 것을 두지 않는다.
- 끌기, 핀치 확대는 태블릿에서 자연스럽지만 늘 버튼 대안(확대 버튼, 앞뒤 버튼)을 함께 둔다.
- 마우스를 올려야만 보이는 정보(hover 툴팁)는 없다. 눌러서 보이게 한다. `@media (hover: hover)`일 때만 hover 효과를 더한다.
- 그림 위 조작 요소는 서로 8px 이상 떨어뜨린다. 손가락은 커서보다 크다.

## 4. 방향 바꾸기와 화면 키보드

- 세로와 가로를 바꿔도 고른 값, 푼 문제, 시뮬레이션 상태가 그대로 남아야 한다. 방향이 바뀔 때 화면을 다시 만들지 말고 CSS로 배치만 바꾼다.
- SVG, canvas는 크기가 바뀌면 다시 그리되 상태는 유지한다(`ResizeObserver`를 래퍼 안 요소에 건다).
- 입력 칸을 누르면 화면 키보드가 아래 절반을 가린다. 입력 칸과 그 확인 버튼이 키보드 위에 보이도록, 입력이 있는 화면은 입력 칸을 화면 위쪽 절반에 둔다.
- 아이패드의 안전 영역(둥근 모서리, 홈 막대)을 위해 아래쪽 여백에 `env(safe-area-inset-bottom)`을 더한다.

## 5. 글자 크기

- 태블릿 학생 화면 본문은 18px(`--fs-body-lg`)을 기본으로 한다. 팔 길이만큼 떨어져서 본다.
- 교실 앞 화면(전자칠판)에 띄우는 화면이면 핵심 설명 24~28px부터 확인한다(`douclass.md`).
- 큰 화면이라고 제목을 키우지 않는다. 위계는 회색 단계와 굵기로 만든다.

## 6. CSS 틀

```css
/* 태블릿 세로: 한 칸, 넓은 본문 */
@media (min-width: 744px) {
  .dc-content .page { max-width: 44rem; margin: 0 auto; padding-left: 1.5rem; padding-right: 1.5rem; }
  .dc-content .choices { grid-template-columns: 1fr 1fr; }
}
/* 태블릿 가로 이상: 두 칸 */
@media (min-width: 1024px) and (orientation: landscape) {
  .dc-content .page { max-width: 72rem; display: grid; grid-template-columns: minmax(0, 3fr) minmax(20rem, 2fr); gap: 2rem; align-items: start; padding-left: 2rem; padding-right: 2rem; }
  .dc-content .stage { position: sticky; top: 1.5rem; }
  .dc-content .stage svg { max-height: calc(100dvh - 8rem); }
}
@media (pointer: coarse) {
  .dc-content { --touch: var(--touch-class); }
}
```

## 7. 점검

- `check.mjs`는 기본으로 390(휴대폰), 820(태블릿 세로), 1180(태블릿 가로) 폭을 본다.
- 가로 태블릿 높이(820 × 1180 기준 가로는 높이 820)에서 첫 화면 핵심이 스크롤 없이 보이는지 화면을 찍어 눈으로 확인한다. 두클래스 A 방식이면 높이를 120px 정도 덜어서 본다.
- 세로와 가로를 바꾼 뒤 상태가 남는지 확인한다.
